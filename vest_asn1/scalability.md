The experiments show that Rust type checking is not the bottleneck. Verification becomes nonlinear in two distinct ways:

  - A single wide SEQUENCE hits Verus’s default resource limit at only 8 mixed-modifier fields.
  - Deeply nested nominal formats show exponential SMT growth: depth 15 takes about 42 seconds, and depth 16 exceeds 60 seconds.
  - Wide CHOICE scales better initially, but also becomes nonlinear around 48–64 variants.

  I generated temporary schemas derived from fixture_ber.asn1 under /private/tmp/vest_asn1-stress; no experiment changes were made to
  the repository.

  ## Methodology

  Each measurement used:

  - The actual vest_asn1 generator.
  - The workspace vest_lib.
  - BER nominal formats with one generated implementation module per format.
  - Warm, offline builds.
  - Default Verus resource limits.
  - 10 verification workers.
  - --time-expanded.
  - A 60-second timeout as the operational definition of “stall”.

  ## Findings

  1. Rust type checking scales well here.
     It remained between 0.24 and 1.04 seconds for every tested case, including cases where Verus exceeded one minute.

  2. Per-format modules improve breadth, but not dependency depth.
     Independent formats can be verified in parallel. A format containing another nominal format still introduces a semantic proof
     chain whose cost grows with nesting depth.

  3. Nominal wrappers do not fully prevent expansion.
     Their invariant methods are trivial, but generated mappings, DeepView, serializer/parser delegation, tag-start reasoning, and
     trait calls still expose relationships through every nested level.

  4. Wide formats and deep formats fail differently.
      - Wide SEQUENCE: one large proof crosses the default rlimit abruptly.
      - Wide CHOICE: nested sum mappers make the parent module increasingly expensive.
      - Deep formats: each successive module has more expensive SMT obligations, producing near-exponential aggregate cost.

  5. The current design is not yet CMS-scalable.
     Real CMS contains both wide records and long named-format dependency chains. Splitting each nominal implementation into its own
     module was valuable, but it is insufficient by itself.

  • The experiments point to a two-part solution:
  
    1. Stronger abstraction boundaries solve deep nesting.
    2. Balanced trees and internal proof boundaries solve wide formats.
  
    Neither module isolation nor solver tuning alone is sufficient.

## ASN.1 tag-disjointness reasoning

ASN.1 `CHOICE`, `OPTIONAL`, and `DEFAULT` require the parser domains of adjacent alternatives to
be disjoint. Earlier proofs tried to establish this by recursively expanding combinator
definitions and saturating global broadcast groups with structural disjointness lemmas. This was
adequate for small handwritten formats, but it was not a scalable strategy for generated schemas:

- nested `CHOICE` trees exposed many equivalent paths through the broadcast rules;
- `OPTIONAL` and `DEFAULT` repeatedly decomposed the same continuation;
- symmetric and union-distribution lemmas increased trigger competition;
- nominal format boundaries hid exactly the tag facts that the solver needed, causing it to
  unfold large schema definitions again;
- adding more broadcast lemmas sometimes made verification slower or less stable rather than
  making the desired proof automatic.

The important observation is that schema dispatch normally depends only on the first ASN.1
identifier octet. There are only 256 such octets. The current representation therefore uses four
64-bit words, one per tag class:

```rust
pub ghost struct Asn1TagLeadMask {
    pub universal: u64,
    pub application: u64,
    pub context_specific: u64,
    pub private: u64,
}

pub ghost struct Asn1StartDomain {
    pub accepts_empty: bool,
    pub tags: Asn1TagLeadMask,
}
```

Within each word, bits 0 through 31 denote primitive leading octets and bits 32 through 63 denote
constructed leading octets. Tag numbers below 31 have distinct bits. All high-tag-number forms
with the same class and constructed bit conservatively share bit 31 in the corresponding half,
because their first octet is identical. Consequently the common-path certificate deliberately
cannot prove two such high tags disjoint; supporting that case precisely would require a
multi-octet prefix certificate.

`HasAsn1Start` connects this finite certificate to parser semantics. Each implementation proves
that a successful parse starts within its advertised domain. Composition is small and direct:

- a required `Pair` inherits the start domain of its left component;
- `Choice`, `Optional`, and `DefaultedFmt` take the bitmap union of their two possible starts;
- `Ref`, `Refined`, `Mapped`, and naming wrappers delegate to their inner format;
- IMPLICIT tagging delegates to the concretely retagged format;
- `Eof` accepts the empty input;
- BER end-of-content boundaries account for both empty input and the EOC tag;
- `ANY` advertises every leading octet except standalone EOC.

One generic proof then converts certificate disjointness into parser-domain disjointness:

```rust
pub broadcast proof fn lemma_disjoint_asn1_starts<Left, Right>(left: Left, right: Right)
    requires asn1_starts_disjoint(left.asn1_start(), right.asn1_start()),
    ensures disjoint_domains(left, right),
```

This separates the proof into two predictable parts. The backend proves once that the bitmap is a
sound over-approximation of accepted inputs. The frontend computes concrete masks from the ASN.1
schema, proves mask unions and intersections with `by (bit_vector)`, and invokes the generic bridge
only at actual dispatch boundaries. The expensive search problem is therefore replaced by
quantifier-free arithmetic over four fixed-size words.

### Nominal boundaries and generated certificates

Generated nominal formats expose sealed start certificates through the ASN.1 nominal macros:

- `tagged_exact` exposes one primitive or constructed leading octet;
- `tagged_identity` exposes both primitive and constructed encodings of the same tag number;
- `untagged_mask` exposes a frontend-computed finite bitmap, normally for `CHOICE`;
- `untagged_any` exposes the `ANY` domain.

The private `lemma_schema_unambiguous` verifies the concrete schema combinator once and connects
its start domain to the nominal certificate. Enclosing formats use the nominal certificate and do
not invoke a child's private schema proof. This prevents disjointness reasoning from recursively
expanding the entire named-format dependency graph.

The generated proof was tightened further by:

- removing per-node `assert(format.unambiguous())` statements;
- removing explicit invocations of child nominal schema lemmas;
- emitting local format bindings only when a disjointness certificate needs them;
- revealing only the exact, empty, union, or disjointness definitions actually used;
- emitting singleton, identity, and BER-boundary bitmap bridge facts only once per schema proof;
- keeping the global ASN.1 broadcast group small and reserving explicit local certificates for
  generated schemas.

Some equalities look redundant mathematically but are necessary abstraction seals in practice.
In particular, CMS verification became unstable when the generator stopped carrying start-domain
equalities across `Ref`, `Refined`, `Mapped`, and required-pair boundaries. Likewise, the following
facts must remain explicit at the relevant boundary:

- each wrapped child has the frontend-computed start mask;
- the two concrete child masks are disjoint;
- a union node has the computed union mask;
- `self.spec_inner().asn1_start() == self.asn1_start()` at the nominal root.

Without these facts, Verus has to rediscover the equality by unfolding nested trait methods and
schema types. Small fixtures may still verify, but the full CMS module does not do so reliably.
Thus the goal is not to minimize the textual proof at all costs; it is to emit the smallest set of
local certificates that prevents semantic structure from leaking across nominal boundaries.

### Result

The final design verifies the checked-in DER, BER, and mixed-rule fixtures as well as the complete
curated CMS module. The last proof-emission cleanup reduced the checked-in fixture from 1,316 to
1,310 verified obligations and the generated CMS module from 3,693 to 3,625 obligations. The CMS
run completed with 0 errors; its reported generated-crate verification time was about 95 seconds

The main lessons are:

1. Fixed-size FIRST certificates are much friendlier to Verus than symbolic sets or recursively
   reconstructed parser semantics.
2. Broadcast automation should prove generic semantic bridges, not search through a generated
   schema tree.
3. The frontend must compute finite tag domains and place proof boundaries because it has the
   schema-wide information needed to do so cheaply.
4. Propositionally redundant boundary equalities can still be essential for modular and stable
   SMT verification.
5. The first-octet bitmap is exact for tag numbers below 31 and intentionally conservative for
   high-tag-number forms.
